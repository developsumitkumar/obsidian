**KEYS:**

|   |   |
|---|---|
|**Primary Key** — Uniquely identifies each row in a table. Cannot contain NULL values, must be unique across all rows, and a table can have only one primary key constraint (though it can span multiple columns).||
|**Composite Key** — A primary key made of two or more columns combined together, where no single column is unique alone, but the combination of all columns together guarantees uniqueness across every row.||
|**Foreign Key** — A column (or columns) in one table that references the primary key of another table, creating a link between them. Enforces referential integrity — values must exist in the referenced table, or be NULL.||
|**Candidate Key** — Any column or column-combination that _could_ qualify as the primary key because it's unique and never null. A table may have several candidate keys; only one gets chosen as the actual primary key.||
|**Alternate Key** — Any candidate key that wasn't chosen as the primary key. It still uniquely identifies rows and is often enforced separately using a UNIQUE constraint, even though it isn't the table's designated primary key.||
|**Unique Key** — Enforces that all values in a column (or column-set) are distinct, like a primary key, but unlike a primary key, it _can_ allow one NULL value and a table can have multiple unique keys.||
|**Super Key** — Any set of one or more columns that uniquely identifies a row, even if it includes extra, unnecessary columns. Every candidate key is a super key, but not every super key is minimal.||
|**Surrogate Key** — An artificial, system-generated identifier (often an auto-incrementing integer or UUID) with no real-world business meaning, used purely as a stable, simple primary key instead of relying on natural data values.||
|**Natural Key** — A primary key made from real, existing data that has inherent business meaning, like an email address or a national ID number, rather than an artificially generated value like a surrogate key.||







**JOINS:**

  

[https://red9.com/blog/sql-joins-venn-diagram/](https://red9.com/blog/sql-joins-venn-diagram/)  
  

|   |   |
|---|---|
|**INNER JOIN** — Returns only the rows that have a match in both tables; anything without a match on either side is dropped entirely from the output.||
|**LEFT JOIN** — Returns every row from the left (FROM) table regardless of a match, filling in NULLs for any right-table columns where no match exists.||
|**RIGHT JOIN** — Returns every row from the right (JOIN) table regardless of a match, filling in NULLs for any left-table columns where no match exists; functionally the mirror of LEFT JOIN.||
|**FULL OUTER JOIN** — Returns all rows from both tables, matched where possible and NULL-filled on whichever side lacks a match; essentially LEFT JOIN and RIGHT JOIN combined.||
|**CROSS JOIN** — Returns every possible combination of rows from both tables with no matching condition at all, producing a full Cartesian product (rows_A × rows_B total rows).||
|**SELF JOIN** — Not a distinct join type but a table joined to itself using two aliases, typically used to compare rows within the same table (e.g., an employee to their manager, both stored in one employees table).||
