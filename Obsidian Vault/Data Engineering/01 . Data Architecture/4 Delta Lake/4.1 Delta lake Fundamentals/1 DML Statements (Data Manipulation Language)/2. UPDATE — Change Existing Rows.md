`UPDATE` means:

> **Modify an existing row that is already present in the table.**

Suppose Silver contains:

```
id    category    amount
------------------------
101   Food         500
102   Travel       800
103   Shopping    1200
```

Later we discover transaction `102` was incorrect.

Correct amount:

```
₹800 → ₹1000
```

We can perform:

```
UPDATE silver_transactions
SET amount = 1000
WHERE id = 102;
```

Result:

```
101   Food         500
102   Travel      1000  ← UPDATED
103   Shopping    1200
```

This is particularly important with **CDC, corrections, changing source records, and late-arriving updates**.

In Delta Lake, the underlying Parquet file generally isn't treated like a traditional database row where bytes are simply edited in place. Delta can write new data files representing the changed state and update the transaction log so the new table version references the correct files.

Conceptually:

```
Delta Version 10

A.parquet
B.parquet
C.parquet

       ↓ UPDATE

new file created
D.parquet

       ↓

_delta_log records:

REMOVE B.parquet
ADD    D.parquet

       ↓

Delta Version 11
```

That's why our earlier discussion about `_delta_log` matters.

### Pipeline connection

Suppose a January transaction gets corrected in September:

```
January Silver
₹500 → ₹900
```

Silver must be updated.

Then our Gold pipeline needs to recognize:

```
January changed
      ↓
Recalculate January aggregate
      ↓
MERGE January into Gold
```

So an UPDATE upstream can create a need for **incremental recomputation downstream**.

### Remember

```
UPDATE
   ↓
"I know this row EXISTS,
but some value changed."
   ↓
Modify it
```
